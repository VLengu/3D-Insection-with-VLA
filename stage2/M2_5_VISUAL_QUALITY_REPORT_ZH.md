# M2.5 验证数据视觉质量报告

## 定位

M2 初版图像只适合调试，不适合直接当作 VLA 验证数据。主要问题是垂直顶视缺乏
立体层次、机械臂遮挡任务区，以及物体、门洞和目标的视觉区分不够强。

M2.5 的目标是把画面提升为“可以用于接口、轨迹和模型闭环验证”的数据，
但仍不把它宣称为最终大规模训练数据。

## 视觉改造

1. 主相机从垂直顶视改为斜俯视正交相机，方位角 `110°`、仰俯角 `-70°`；
2. Panda 改用更紧凑的标准 ready pose，机械臂位于画面左侧，不再横跨整个任务区；
3. 桌面改为蓝灰色，与白色 Panda 形成明确对比；
4. 待抓物体为红色，目标区为蓝色圆形；
5. 中央 over 候选区用黄色表示，侧方 side 门洞用绿色表示；
6. 外围墙和填充墙保持中性灰，避免与任务元素争夺注意力。

几何伪记录中的初始末端状态也已改为与 MuJoCo reset 的 ready pose 一致，
避免后续导出时出现“图像中的机器人姿态与元数据不一致”。

新画面的语义是：

```text
白色机械臂 + 红色物体 -> 黄色中央越障 / 绿色侧方门洞 -> 蓝色目标区
```

## 配对因果边界

为避免高度通过遮挡、阴影或边缘像素泄漏，环境中现在有两层几何：

- **可见外壳**：同一 pair 共享，只服务于 RGB 观测；
- **隐藏碰撞体**：保留 over-only / side-only 的真实 Z 差异，决定物体是否可通过。

因此配对成员的策略 RGB 字节级相同，但正确动作仍必须根据 3D oracle 改变。
`render_physical()` 可单独显示真实碰撞高度，仅供开发和失败诊断。

## 自动可见性门

使用 MuJoCo segmentation buffer 统计 256×256 画面中的有效像素。全部 44 个 pair 的
最差结果为：

| 关键元素 | 拒绝阈值 | 全数据最小值 |
|---|---:|---:|
| 红色物体 | 120 px | 164 px |
| 蓝色目标 | 300 px | 459 px |
| 黄色中央路线 | 500 px | 721 px |
| 绿色侧方路线 | 500 px | 795 px |
| Panda 可见部分 | 3000 px | 4285 px |

验收结果：`44 / 44` pair 通过视觉质量门，`44 / 44` pair 的策略 RGB 字节级相同。

## 物理回归

更换相机、颜色和 Panda 初始姿态后，已重新运行全部回放：

- 正确路线：`88 / 88` 成功；
- 强制错误路线：`88 / 88` 被物理拒绝；
- 碰撞失败：44；
- 最大搬运高度失败：44；
- episode 长度：48–116 步。

## 结论

新版图像可用于当前的验证数据：用于 LeRobotDataset round-trip、数据加载、
TinyContractVLA、配对评价和注入边界检查。

它仍不是最终正式 GPU 训练数据。正式数据生成前，还应根据 Tiny 模型的失败案例决定
是否增加腕部相机、纹理随机化和更宽的视觉 OOD。
